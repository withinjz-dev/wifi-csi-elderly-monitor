1. 개발 개요
================================================================================

1.1 개발 배경
--------------------------------------------------------------------------------
국내 65세 이상 1인 가구는 200만 세대를 넘어섰고 고독사는 증가 추세다. 기존 안전
확인 수단은 각각 명확한 한계를 가진다.

  CCTV/카메라      사생활 침해로 침실·화장실 등 사고 빈발 공간에 설치 불가
  웨어러블         착용 순응도 낮음. 특히 수면 중·목욕 중 미착용
  PIR 동작감지     움직임 유무만 판별 -> 수면 중 정지와 의식 소실을 구분 못함
  응급호출 버튼    의식이 없으면 누를 수 없음

세 번째가 본 프로젝트의 출발점이다. "장시간 무동작"을 위급 신호로 삼는 시스템은
매일 밤 수면 시간마다 오탐을 일으키므로 실사용 시 알림을 꺼두게 되어 무력화된다.

1.2 개발 동기
--------------------------------------------------------------------------------
WiFi 전파는 공간을 통과하며 인체에 반사·회절되고, 수신 칩은 이 왜곡을 CSI(Channel
State Information)라는 부반송파별 진폭·위상 데이터로 이미 계산하고 있다. 별도 센서
없이, 통신용으로 존재하는 데이터만으로 공간 내 물리적 변화를 관측할 수 있다.

핵심 아이디어: 수면 중 완전히 정지한 것처럼 보여도 흉곽은 분당 12~20회 주기로
미세하게 움직인다. 이 주기성이 CSI에 남는다면 다음과 같이 구분된다.

  정상 수면 = 큰 움직임 없음 + 호흡 주기성 있음
  위급 상황 = 큰 움직임 없음 + 호흡 주기성 없음

PIR이 원리적으로 구분할 수 없던 두 상태를 분리하는 것이 본 시스템의 목표다.

1.3 개발 목표
--------------------------------------------------------------------------------
  핵심   카메라·웨어러블 없이 WiFi 신호만으로 재실과 호흡을 판별하고, 수면 시간대에
         호흡 신호가 지속 소실되면 로컬 알림(LED·부저)을 발생시키는 프로토타입
  부가1  ESP32 단독으로 전 과정을 수행하는 standalone edge 시스템으로 구현
         (호스트 PC는 개발·디버깅 용도로만 사용)
  부가2  공간·사용자별 임계값을 자동 보정하는 적응형 알고리즘
  비목표 심박수 측정, 낙상 '순간' 포착, 다인·다공간 대규모 검증
         (1주 프로토타입 기간 내 신뢰성 확보 불가로 판단하여 명시적 제외)

1.4 개발 필요성
--------------------------------------------------------------------------------
  1) 프라이버시 보존 - 영상·음성 미수집. 수집 데이터는 무선 신호 왜곡 계수뿐이며
     영상·음성 정보를 직접 포함하지 않아 CCTV 대비 프라이버시 침해 우려가 낮다.
     (단, WiFi CSI로 보행 패턴 등을 통한 간접 식별 가능성은 별도 연구 영역이며
     본 시스템이 이를 원천 차단함을 주장하지는 않는다) CCTV 설치가 막혔던
     침실에도 적용 가능
  2) 인프라 유연성   - 가정에 WiFi 공유기가 있으면 그 비콘 신호를 TX로 재활용해
     RX 보드만 설치하면 된다(설치 부담 최소화). 공유기가 없는 가구는 기존 방식대로
     TX/RX 두 대가 폐쇄형 자체망을 구성해 인터넷 회선 없이도 동일하게 동작한다
  3) 온디바이스      - 신호처리·판정·알림이 전부 로컬. 클라우드 전송 경로 자체가 없음
  4) 저비용          - 부품비 약 2만원

1.5 유사 사례 비교
--------------------------------------------------------------------------------
독거노인 안전 모니터링은 이미 예산이 투입된 검증된 문제 영역이며, 여러 상용·공공
서비스가 존재한다. 아래는 조사한 세 사례와 본 시스템의 원리적 차이다.

  (1) 지자체 PIR 감지등 (예: 진천군, 2020, 예산 1억원/220가구)
      움직임 미감지 시간을 8/12/24시간으로 나눠 주의/경보/위험 알림. PIR은 원리상
      "정지+호흡"과 "정지+무호흡"을 구분할 수 없어, 오탐을 피하려면 대기시간을
      길게 둘 수밖에 없다. 8시간 지연은 설계 실수가 아니라 PIR의 원리적 한계가
      만든 결과다.

  (2) 보건복지부 독거노인·장애인 응급안전안심서비스 (전국 단위 국가 서비스)
      활동량감지기·레이더센서로 움직임뿐 아니라 심박·호흡까지 측정해 의식 소실을
      판별한다. 본 시스템과 목표가 가장 근접한 선행 사례다. 차이는 센싱 매체다 -
      전용 FMCW/mmWave 레이더 칩(개당 3만~15만원대)을 쓰는 반면, 본 시스템은
      통신용으로 이미 존재하는 WiFi 칩(개당 3천~7천원대)의 CSI를 재활용한다.
      즉 "레이더급 기능을 범용 저가 부품으로 구현할 수 있는가"가 본 프로젝트의
      실질적 검증 대상이며, 국가 서비스가 이미 존재한다는 사실이 이 접근의
      경제성 가치를 오히려 뒷받침한다.

  (3) 상용 홈케어 허브 (예: 동작감지 센서+충격감지 태그+허브 구성)
      낙상 시 충격을 태그(가속도계, 착용형)로 감지하고 경중도별 문자/ARS 순차
      알림, 비상벨을 지원한다. 충격감지·비상벨은 모두 "낙상이 발생했거나 의식이
      있어야" 작동한다. 낙상 없이 조용히 의식을 잃는 경우(뇌졸중, 심정지, 저혈당
      쇼크 등)는 이 조합으로도 감지되지 않고, 결국 PIR류 무동작 타임아웃에
      의존하게 된다. 또한 태그는 착용형이라 미착용 시(수면 중, 목욕 중) 무력화되는
      순응도 문제를 그대로 가진다.

  종합: 세 사례 모두 "낙상/충격/의식/버튼 조작" 중 하나를 요구하거나, 그것이
  없을 때는 장시간 무동작 타임아웃에 의존한다. 본 시스템의 좁지만 실질적인
  차별점은 이 마지막 구멍 - 충격도 조작도 없이 조용히 반응이 없어지는 경우를
  약 60초 단위로 감지하려는 시도라는 점이다. 다만 (2)와 원리적으로 거의 동일한
  접근이 이미 국가 서비스로 존재하므로, 본 프로젝트의 기여는 "새로운 감지 원리"가
  아니라 "동일 기능을 훨씬 저렴한 범용 부품으로 재현할 수 있는가"에 있음을
  분명히 한다.

2. 개발 환경 설명

2.1 하드웨어
--------------------------------------------------------------------------------
  ESP32-WROOM-32 개발보드(38핀) x2   TX(송신) / RX(수집·판정·알림)
  브레드보드 830핀 x1                알림 회로
  수동형 부저 x1                     청각 알림 (GPIO5, PWM 구동)
  LED(적색) x1 + 220옴 저항 x1       시각 알림 (GPIO4)
  점퍼 와이어 x6, USB 케이블 x2
  총 부품비 약 2만원

  물리 구성 (하이브리드: 호흡 감지와 재실 판정을 서로 다른 신호원으로 분리)

    [ESP32 TX]  ~~~~~ 2.4GHz WiFi ~~~~~>  [ESP32 RX]
     active_sta      초당 11~13 패킷        active_ap (edge)
     전원만 필요      ^ 인체 반사·회절 ^     CSI 취득 -> 호흡 판정 -> 알림
                                             |  ^
                                             |  |  결합 목록 조회(10초 주기)
                                             |  +---- [거주자 스마트폰]
                                             |         재실/외출 판정 전용
                                       GPIO4 --[220옴]--[LED]--+
                                       GPIO5 --[Passive Buzzer]-+
                                       GND  -------------------+

  전파 경로: TX-RX 직선 경로(LoS) 상에 인체가 위치하도록 배치. 호흡에 의한 흉곽
  변위는 밀리미터 단위이므로 인체가 주 경로를 벗어나면 CSI 변화가 잡음에 묻힌다.
  실측 유효 감지 거리는 TX-RX 간 약 1~2m.

  GPIO 결선
    GPIO4  LED(+220옴 직렬)   디지털 HIGH/LOW
    GPIO5  수동형 부저        LEDC PWM 2,700Hz duty 50%
    GND    공통 접지
  주의: 부저가 수동형이라 정적 HIGH로는 발음되지 않는다. LEDC 페리페럴로 가청
  주파수 PWM을 인가해야 한다 (4.2절 참조).

--------------------------------------------------------------------------------

  툴체인              xtensa-esp32-elf 8.4.0, CMake, Ninja

  분석용 Python       3.13 (numpy, scipy, scikit-learn, matplotlib, pyserial)
  개발 OS             macOS (Apple Silicon)

  소프트웨어 계층 (L1만 오픈소스, L2~L4는 자체 개발)

    L4  적응형 보정   calibrate.py / train_classifier.py  [호스트, 개발용]

    L1  CSI 수집      ESP32-CSI-Tool                      [오픈소스]

2.3 기능 설계도 (전 과정 ESP32 내부)
--------------------------------------------------------------------------------
  WiFi task --(CSI callback: memcpy만)--> xQueue --> CSI task --> ring buffer
                                                                       |
                                                        Decision task -+ (10초)

    원시 CSI (52 서브캐리어 I/Q)
      -> 선별된 8개 서브캐리어 power = I^2 + Q^2   (sqrt 생략)
      -> 100ms 시간 빈 -> 균일 10Hz 스트림
      -> 256 샘플 링버퍼 (25.6초 창)
      -> 최소자승 직선 추세 제거
      -> 0.2~0.5Hz IIR 대역통과 (RBJ biquad)
      -> Goertzel 뱅크 7개 빈
      -> 피크 주파수 + 스펙트럼 집중도
      -> 주파수 일관성 확인 (최근 3창)
      -> 상태 판정 + 히스테리시스
      -> LED / 부저

  상태 판정 분기

                       움직임 감지
                  +----------------------> ACTIVE
                  |
    윈도우 -------+  움직임 없음
                  |
                  v
          호흡 주기성 있는가?
             |          |
            YES        NO
             |          |
             v          v
       SLEEP_NORMAL  NO_RESPONSE
                        |
              60초 지속 AND 수면시간대?
                        |
                       YES
                        |
              재실 확인 (3.4절)
                아래 중 하나라도 "외출"이면 억제
                  - 스마트폰이 AP에 결합되어 있는가?   [주 신호]
                  - CSI 이탈 버스트가 관측되었는가?    [보조 신호]
                        |
                    재실 확정 --> EMERGENCY (LED + 부저)

    데이터 자체가 없으면(NO_DATA) 60초 지속 시 --> FAULT (LED만, 부저 없음)

    active_ap/main/main.cc   EDGE_MODE 컴파일 스위치
                             1 = standalone, 0 = 원시 CSI 스트리밍(레퍼런스 검증용)
    edge_mqtt.h         MQTT 발행 스캐폴드 (EDGE_ENABLE_MQTT, 기본 비활성·미검증)

    validate_embedded.py        임베디드 알고리즘의 Python 미러 + 교차검증
    validate_normalization.py   임계값 정규화 설계 3안 비교 검증
    calibrate.py                Otsu 기반 공간별 임계값 산출 (개발 분석용)
    train_classifier.py         로지스틱 회귀 학습·교차검증
    capture_csi.py              원시 CSI CSV 수집
    analyze_breathing.py        오프라인 대역통과·FFT 호흡 검출

3.2 주요 함수
--------------------------------------------------------------------------------
  [펌웨어]
    alert_init()          GPIO4 출력 설정, GPIO5 LEDC 타이머(2700Hz/10bit) 구성
    alert_set_level()     ALERT_NONE / ALERT_FAULT(LED만) / ALERT_EMERGENCY(LED+부저)
    edge_csi_rx_cb()      CSI 콜백. memcpy 후 큐 전송만 수행. 큐가 차면 드롭 카운트
                          만 올리고 즉시 반환 (Wi-Fi 태스크를 절대 블로킹하지 않음)
    edge_ingest_frame()   선별 서브캐리어 power 평균 -> 100ms 시간 빈 -> 링버퍼
    edge_score_subcarriers() / edge_finish_selection()
                          서브캐리어별 대역통과 분산비 산출 후 상위 8개 선택
    edge_biquad_step()    RBJ 대역통과 1샘플 처리
    edge_goertzel_power() 단일 주파수 Goertzel. 상태변수 2개, 샘플당 곱 1·합 2회
    edge_goertzel_analyze() 7개 빈 일괄 분석 -> 피크 주파수 + 집중도
    edge_autocorr_peak_freq() 자기상관 기반 독립 확인 경로 (lag 20~50)
    edge_baseline_update()  정지 구간 mu/sigma 갱신. 부트스트랩은 러닝평균,
                            이후 EWMA. 이상 상태에서는 호출 금지
    edge_state_step()     상태 판정 + 2종 streak 관리 + 알림 결정
    edge_decision_task()  10초 주기. 추세제거 -> 대역통과 -> Goertzel -> 판정 -> 알림

  [호스트]
    otsu_threshold()      1차원 Otsu. 클래스간 분산 w1*w2*(mu1-mu2)^2 최대화
    classify()            레퍼런스 판정 (Welch PSD 기반)

3.3 기술적 차별성
--------------------------------------------------------------------------------
(1) 호흡 주기성을 이용한 무동작의 이원 분해

    상태            움직임   호흡신호   해석
    ACTIVE          있음     -          활동 중 (정상)
    SLEEP_NORMAL    없음     있음       수면 중 (정상)
    NO_RESPONSE     없음     없음       부재 또는 이상 상황

    PIR 센서로는 원리적으로 2행과 3행을 구분할 수 없다.

(2) 임베디드 환경에 맞춘 신호처리 재설계

    PC 프로토타입의 범용 Welch/FFT 스펙트럼 분석을 그대로 이식하지 않고, 관심
    대역(0.2~0.5Hz)만 선택적으로 계산하는 Goertzel 기반 경량 검출기로 재설계했다.

    정직한 성능 평가: N=256, 빈 7개 기준 곱셈 약 1,792회로 256점 실수 FFT(약
    4,096회) 대비 2~3배 수준이다. "연산량이 극적으로 작다"고는 말할 수 없다.
    실질적 이점은 다음 세 가지다.
      - 복소 스크래치 버퍼가 불필요 (메모리 절감)
      - 빈을 fs/N 배수가 아닌 정확한 주파수(0.20, 0.25, ... 0.50Hz)에 배치 가능
      - 외부 DSP 라이브러리 의존 없음

    보조로 자기상관(lag 20~50 샘플) 경로를 병행한다. 두 방법은 실패 양상이 달라
    상호 검증에 유리하다.

(3) 데이터 축소 설계

    HT20 LLTF 프레임은 52개 유효 서브캐리어를 int8 I/Q로 전달한다. 20초를 원시로
    저장하면 창당 약 23kB이지만, 본 시스템의 질문은 '움직이는가 / 정지인가 /
    호흡 주기성이 있는가'뿐이므로 자세 복원이 필요 없다. 따라서 매 프레임을 즉시
    스칼라 1개로 압축하고 링버퍼는 256 float(1kB)만 유지한다.

    진폭 대신 power(I^2+Q^2)를 사용하고 sqrt를 생략했다. 변화 검출 통계로는
    sqrt가 정보를 더하지 않으면서 서브캐리어당 초월함수 1회를 요구한다. 단,
    완전히 무해하지는 않다 - A+B*sin(wt)를 제곱하면 2w 성분이 생긴다. 호흡에서는
    B<<A이므로 이 고조파는 기본파보다 훨씬 낮고, Goertzel 뱅크는 0.2~0.5Hz만
    읽으므로 실질 영향은 없다.

(4) 다층 오탐 억제

    단일 윈도우 판정은 잡음에 취약하다는 실측(호흡 중임에도 18% 오탐)에 근거해
    3중 필터를 설계했다.
      a. 선형 추세 제거 - 평균 차감만으로는 저주파 드리프트가 대역 하단(0.15Hz)에
         누설되어 무인 상태에서도 허위 피크가 발생. 최소자승 직선 제거 적용 및
         대역 하한을 0.2Hz로 상향
      b. 주파수 일관성 - 실제 호흡은 1분 내 급변하지 않으나 잡음 피크는 매 창
         무작위 위치에 나타난다. 최근 3창 중 하나라도 +-0.12Hz 이내 일치할 때만
         호흡으로 확정
      c. 히스테리시스 - 연속 6회(60초) 지속 시에만 알림 발동

    검증: 실제 호흡 녹화본에서 연속 미확정 구간이 최대 2회(20초)에 그쳐 알림
    발동 기준(6회)에 도달하지 않음. 정상 수면 중 오경보 위험이 없음을 정량 확인.

(5) 시공간 맥락 인지

    동일한 NO_RESPONSE라도 발생 시각에 따라 의미가 다르다. 낮의 무응답은 대개
    외출이므로 수면 시간대(22시~7시)에만 응급 알림을 활성화한다.

(6) 센서 고장과 사람 이상의 분리 [실기 테스트로 발견·수정]

    초기 설계는 NO_DATA(센서 실명)와 NO_RESPONSE(사람 이상)를 하나의 카운터로
    처리했다. 실기 테스트에서 TX 보드 전원이 끊기자 이 카운터가 60초를 채워
    응급 부저가 울렸다. 실제 제품이라면 배터리 나간 송신기가 응급 경보를 울리는
    셈이고, 이는 보호자가 알림 전체를 무시하게 만드는 가장 위험한 실패 양상이다.

    수정: 카운터와 알림을 각각 2종으로 분리
      ALERT_EMERGENCY  LED + 부저.  방은 보이는데 호흡이 없음. 수면시간대 한정
      ALERT_FAULT      LED만, 부저 없음.  방이 안 보임. 시간대 무관(고장은 언제든
                       알려야 함)

(7) 적응형 임계값 자동 보정

    Day 5 초기 결과는 공간별 최적 임계값이 5.18배 차이난다는 것이었고, 이를
    "공간마다 임계값이 달라야 한다"는 근거로 삼았다. 그러나 후속 검증(5.1절)에서
    그 해석에 결함이 있음이 드러났고, 설계를 다음과 같이 수정했다.

    기기는 임계값을 학습하지 않는다. 정지 상태 baseline(mu, sigma)만 학습하고
    펌웨어 상수 k를 적용한다.

        움직임 판정 <=> rssi_std > mu_still + K * sigma_still   (K = 3.0)

    이점
      - 기기에서 Otsu를 돌릴 필요가 없다. NVS에 저장할 값은 실수 2개뿐
      - 부트스트랩은 러닝 평균으로 빠르게 수렴, 이후 EWMA(alpha=0.002, 시정수
        약 80분)로 가구 이동·계절 변화를 천천히 추종
      - 이상 상태에서는 baseline 갱신을 금지한다. 그렇지 않으면 이상 상태 자체를
        정상으로 학습해 경보를 스스로 무력화한다

3.4 재실 판정과 호흡 감지의 신호원 분리 (하이브리드 구조)
--------------------------------------------------------------------------------

  본 시스템의 최대 미해결 과제는 "외출"과 "응급"이 CSI 상에서 동일하게
  NO_RESPONSE로 보인다는 점이었다. 수면시간대 게이팅은 완화책일 뿐 해결책이
  아니다. 검토한 세 가지 안과 채택 근거는 다음과 같다.

    A안  CSI 2-zone (침실/현관에 RX 2대)
         [폐기] ESP32는 미결합(promiscuous) 상태에서 타 BSS의 유니캐스트
         프레임에 대해 CSI를 사실상 산출하지 못함을 실기에서 확인했다
         (20초간 콜백 1~2회). 4.7절 참조.

    B안  스마트폰을 CSI 송신원으로 사용 (전용 TX 보드 제거)
         [폐기] 호흡 대역 관측에 필요한 초당 수~수십 프레임을 유지하려면
         폰의 WiFi 절전 진입을 상시 차단해야 하고, 이는 폰 배터리 소모를
         유의미하게 증가시킨다. 독거노인의 폰 방전은 그 자체가 안전 위험이며
         (연락 수단 소실 + 본 시스템의 감지 불능), 안전장치가 안전을 훼손하는
         구조가 되므로 트레이드오프가 아닌 설계 결함으로 판단했다.

    C안  하이브리드 - 신호원 분리                                   [채택]
         호흡 감지: 전용 TX(또는 공유기 비콘). 상시 급전되는 기기가 송신
                    부담을 진다.
         재실 판정: 스마트폰의 AP 결합 여부만 조회. 폰이 스스로 유지하는
                    결합 상태를 읽기만 하므로 폰에 추가 부하가 없다.

  C안의 실패 방향도 안전한 쪽이다. 폰을 집에 두고 외출하면 재실로 오판하지만,
  이는 경보를 놓치는 방향이 아니라 과잉 경보 방향이다.

  재실 판정의 4단 구조 (구체적일수록 우선, 각 단계는 다음 단계로 축퇴)

    1단 PINNED     빌드 시 MAC 지정. 정확하지만 OS의 네트워크별 무작위 MAC
                   정책에 취약하다. 본 개발 중에도 최초 관측 MAC과 실제 결합
                   MAC이 달랐다. 기본값은 미설정이며, 아래 2~4단이 동작한다.
    2단 REGISTERED 설치 시 1회 등록(BOOT 버튼 또는 REGISTER 명령). 자동 학습이
                   근거를 쌓기 전 수일간의 공백을 메운다. 자동 채택이 이를
                   덮어쓰지 않는다.
    3단 ADOPTED    자동 학습. 거주자의 조작이 전혀 필요 없다. 채택 규칙은
                   아래 참조.
    4단 ANY        자격을 갖춘 단말이 하나라도 결합되어 있으면 재실로 간주.
                   본 AP는 집 공유기가 아니라 우리 보드가 만든 폐쇄망이고
                   설치 시 거주자 폰만 연결하므로 성립한다. MAC 무작위화의
                   영향을 원천적으로 받지 않는다.

  자동 채택 규칙 - "가장 오래 붙어있는 기기"가 아니라 "드나드는 기기"

    직관적인 규칙은 "가장 자주 존재하는 단말을 채택"이지만 이는 틀렸다.
    상시 전원 기기(TV, 거치된 태블릿)가 선택되며, 한 번도 부재한 적 없는
    기기는 재실 정보를 전혀 담지 않는다. 그런 기기를 채택하면 영구히
    "재실"로 보고하여 모든 응급 경보를 조용히 무력화한다.

    따라서 채택 조건을 "이탈과 복귀가 3회 이상 관측된 단말"로 정의했다.
    사람과 함께 이동하는 기기만이 사람의 재실 여부를 알려줄 수 있기
    때문이다. 이 규칙은 MAC 무작위화도 자동 복구한다 - 회전된 MAC은 새
    단말로서 자체 이탈 이력을 쌓기 시작하고, 기존 MAC은 오래 미관측 시
    채택이 해제된다(7일).

    복수 단말이 조건을 넘길 경우 선착순이 아니라 이탈 횟수가 가장 많은
    단말을 채택한다. 방문자 폰도 기준을 넘길 수 있지만, 거주자 폰은 매일
    드나들며 격차를 계속 벌리므로 순위 기반이 더 견고하다.

  모든 단계에서 불확실하면 "재실"로 판정한다. 재실은 경보를 그대로 유지하는
  방향이고, 경보를 억제하는 "외출" 판정에만 적극적 근거를 요구한다.

  설치 시 등록 절차 - 애매하면 추측하지 않고 거부한다

    REGISTER 명령을 내리면 60초 창이 열리고, 설치자가 거주자 폰의 WiFi를 껐다
    켜면 그 단말이 등록된다. 명령 시점에 이미 결합된 단말은 후보에서 제외되어
    "방금 다시 나타난 기기"만 신호가 된다.

    초기 구현은 창 안에서 처음 나타난 단말을 즉시 등록했다. 실기 테스트에서
    이 방식은 곧바로 엉뚱한 단말을 등록했다 - 폐쇄망에 3대가 상주하던 상황에서
    폰보다 다른 기기가 근소하게 먼저 재결합했기 때문이다. 잘못된 등록은 외출
    억제를 조용히 무력화하므로 겉으로는 정상으로 보인다. 따라서 규칙을 "창이
    끝날 때까지 기다렸다가 새로 나타난 단말이 정확히 1대일 때만 등록"으로
    바꾸고, 2대 이상이면 등록을 거부하고 관측된 MAC 목록을 출력하도록 했다.

    다만 본 환경처럼 여러 기기가 항상 함께 재결합하면 자동 판별이 영구히
    불가능하다. 이 경우를 위해 REGISTER <MAC> 형식을 두어, 거부 시 출력된
    목록에서 설치자가 직접 지정할 수 있게 했다. 영원히 거부만 하는 것보다
    사람이 결정하도록 열어두는 편이 낫다는 판단이다.

    기존 등록은 REGISTER 시작 시점에 먼저 해제된다. 등록에 실패했을 때 낡거나
    잘못된 결속이 남아있는 것보다, 아무것도 결속되지 않은 채 4단(ANY)으로 축퇴해
    HOME으로 판정하는 쪽이 안전하기 때문이다.

  학습 상태는 NVS에 영속화된다. 재부팅으로 며칠간의 관측이 사라지면 자동 학습이
  사실상 동작할 수 없기 때문이다. 기록 대상은 단말 식별자와 이탈 횟수뿐이며,
  타임스탬프는 부팅 기준 상대값이라 재부팅 후 무의미하므로 저장하지 않는다.
  쓰기는 실제 변화가 있을 때만 수행되어 하루 수 회 수준이다.

  실기 검증
    - 1단 PINNED: 등록 MAC 매칭 -> "presence confirmed HOME" 확인
    - 4단 ANY: presence=any/HOME 상태 라인 출력 확인
    - NVS 영속화: 단말 3대 학습 후 리셋 -> 복원 확인. 등록 후 리셋 시
      "registered device is FC:E8:C0:**:**:**"까지 복원 확인
    - 2단 REGISTERED: REGISTER 명령 -> 창 개방(presence=registering) ->
      2대 동시 재결합 -> 등록 거부 + 후보 MAC 2건 출력 확인.
      이어서 REGISTER <MAC>으로 거주자 폰 지정 -> 등록 성공 확인
      (오등록을 실기에서 재현하고, 수정 후 거부되는 것까지 확인함)
    - 자격 규칙: 단말 3대가 결합된 상태에서도 이탈 이력이 없어 어느 것도 4단
      자격을 얻지 못했고, 판정은 "미관측 -> HOME"이라는 안전 기본값으로
      유지되었다. 상시 결합 기기가 재실 판정을 점유하지 않음을 실측 확인
    - 3단 ADOPTED: 채택에 실제 외출 3회가 필요해 프로토타입 기간 내 미검증

  부가 관측: 위 검증 중 전용 TX 보드가 없는 상태에서도 결합된 스마트폰의
  트래픽만으로 초당 약 10프레임의 CSI가 수신되었다(cb 599->811/20초,
  ringfill=256). 즉 B안이 기술적으로 불가능해서가 아니라 배터리 소모라는
  운용상의 이유로 폐기되었음을 뒷받침한다.

  보조 신호로 CSI 기반 이탈 추정(EDGE_K_DEPARTURE = 6.0 sigma)을 병행한다.
  RX 근처를 통과하는 큰 움직임 버스트를 "나감"으로 읽는 휴리스틱으로, 조용히
  나가거나 먼 경로로 나가면 놓치므로 단독으로는 신뢰할 수 없다. 두 신호는
  실패 양상이 달라 어느 하나라도 외출을 지시하면 경보를 억제한다.

4.1 레거시 프레임워크와 최신 툴체인의 3중 버전 충돌
--------------------------------------------------------------------------------
  증상: idf.py 실행 시 ModuleNotFoundError: No module named 'click'
  원인이 하나가 아니라 3개가 연쇄된 상황이었다.

    1) CSI API가 ESP-IDF v4.3 고정을 요구하는데 시스템 기본 Python이 3.13이어서
       v4.3이 요구하는 gevent 등 구버전 패키지가 컴파일 실패
       -> Homebrew로 python@3.10 설치 후 IDF 전용 가상환경 재생성
    2) 최신 setuptools(84.x)가 pkg_resources를 제거했으나 IDF v4.3이 이에 의존
       -> 해당 가상환경에 setuptools<81 고정
    3) 최신 CMake(4.x)가 IDF 내장 mbedtls의 cmake_minimum_required(<3.5)를 거부
       -> 환경변수 CMAKE_POLICY_VERSION_MINIMUM=3.5

  재발 방지: 세 설정을 묶은 get_idf 셸 alias 등록. 새 터미널에서 한 줄로 복원.

4.2 원인이 중첩된 알림 회로 무동작
--------------------------------------------------------------------------------
  증상: 펌웨어가 ALERT_ON 수신을 정상 에코함에도 LED·부저 모두 무반응

  진단 전략: 실시간 모니터링 스크립트와 별개로 원시 시리얼 송수신 전용 진단
  스크립트를 작성해 펌웨어가 명령을 정상 처리함을 먼저 확인하고 문제를 하드웨어로
  국소화했다.

    1) 브레드보드 전원 레일(-)이 중간에서 단선된 규격
       -> 레일 경유 대신 직결 배선으로 검증 후 확정
    2) 저항과 LED가 동일 행(row)에 정렬되지 않아 전기적 미연결
       -> LED 회로 전체를 인접 3개 행에 재배선
    3) 부저가 수동형(Passive)이어서 정적 HIGH로는 발음 불가
       -> LEDC 페리페럴 2,700Hz PWM 구동으로 전환

  교훈: 원인이 중첩된 하드웨어 문제는 텍스트 추론보다 한 번에 하나의 변수만
  격리하는 물리 검증이 압도적으로 빠르다. 특히 3번은 소프트웨어가 완전히 정상인
  상태에서도 발생하는 부품 특성 문제로, 데이터시트 사전 확인의 중요성을 보여준다.

4.3 CSI 수집 - 파이프 리다이렉션 미동작 및 좀비 프로세스
--------------------------------------------------------------------------------
  증상: 공식 문서 안내대로 idf.py monitor | python ... > out.csv 실행 시 0바이트

  원인: ESP-IDF v4.3의 idf_monitor가 표준출력 파이프가 아닌 터미널에 직접 출력
  하는 구현이어서 후속 파이프로 데이터가 전달되지 않았다. 더불어 보조 스크립트가
  파이프 종료 시 정상 종료되지 않고 CPU 100%를 점유하는 좀비 프로세스로 남아
  시스템 전체를 지연시켰다.

  해결: idf.py monitor를 경유하지 않고 pyserial로 포트를 직접 개방하는 자체 수집
  스크립트 작성. 이 과정에서 두 가지를 함께 해결했다.
    - 포트 개방 시 DTR/RTS 미해제로 보드가 리셋 상태 고착 -> dtr/rts = False 명시
    - 파일 출력 버퍼링으로 강제 종료 시 데이터 유실 -> 라인 버퍼링 적용

4.4 실시간 전환 과정에서 드러난 3개 판정 결함
--------------------------------------------------------------------------------
  오프라인 분석에서 정상 동작하던 로직이 실시간 환경에서 결함을 드러냈다.

    1) 모든 윈도우가 NO_DATA
       원인: 정규식이 '],'를 요구했으나 실시간 원시 데이터는 ']'로 종료
             (파일 저장 시에만 타임스탬프 쉼표가 추가됨)
       해결: 정규식을 \[(.*)\] 로 수정
    2) 신호 두절 후에도 마지막 상태가 무한 반복
       원인: 버퍼 정리가 신규 데이터 수신 시에만 수행되어 완전 두절 시 버퍼 동결
       해결: 수신 여부와 무관하게 벽시계 시각 기준으로 매 루프 정리
    3) 무인 상태에서 SLEEP_NORMAL 오판
       원인: 평균 차감만 수행해 저주파 드리프트가 대역 하단에 허위 피크 생성
       해결: 선형 추세 제거 + 대역 하한 0.2Hz 상향

  3번은 사용자가 실제로 방을 나갔음에도 정상 수면으로 판정되는 치명적 결함이었으며,
  실시간 실사용 테스트가 없었다면 발견하지 못했을 문제다.

4.5 임베디드 이식 과정에서 실기 테스트로만 발견된 버그
--------------------------------------------------------------------------------
    1) HT20 LLTF 서브캐리어 매핑 오류
       교과서 배치는 슬롯 1~26 / 38~63이지만, 실제 캡처 300프레임을 측정하니 본
       하드웨어는 6~31 / 33~58을 사용했다(슬롯 32 = DC). 가정대로 구현했다면
       가드밴드를 읽으면서도 아무 에러 없이 동작했을 것이다.
       -> 실측 기반으로 매핑 수정

    2) CSI 초기화 순서
       esp_wifi_set_csi(1)을 esp_wifi_set_csi_config() / set_csi_rx_cb()보다
       먼저 호출해야 한다. 직관적인 순서(설정 -> 콜백 -> 활성화)로 작성하면
       에러가 전혀 발생하지 않으면서 콜백이 영영 호출되지 않는다. 외부에서는
       frames=0으로만 보여 진단이 매우 어렵다.
       -> 콜백 진입 카운터(cb, nullbuf, lastlen)를 펌웨어에 내장해 "드라이버가
          호출하지 않는 것"과 "호출되지만 하위에서 걸러지는 것"을 구분 가능하게 함

    3) NO_DATA와 NO_RESPONSE의 혼동 (3.3절 (6) 참조)

4.6 무선 링크 및 전원 토폴로지 제약
--------------------------------------------------------------------------------
  증상: 두 보드 모두 펌웨어는 정상인데 결합(association)이 되지 않음

  진단: 두 보드의 역할을 서로 맞바꾸는 대조실험을 수행한 결과, 실패가 보드를
  따라가지 않고 전원 공급원을 따라갔다. 동일한 벽 충전기 케이블에서 AP 역할은
  정상 동작하나 STA 역할은 결합에 실패한다.

  해석: 전류 프로파일 차이. AP 모드는 대부분 비콘만 송출하는 저부하이지만,
  active_sta는 스캔·결합 후 패킷을 지속 송신하는 최고 부하 상태다. 케이블 저항이
  크면 이 순간 전압 강하로 결합에 실패한다.

  운용 규칙: TX를 안정적인 전원에, RX를 상대적으로 여유 없는 전원에 배치.
  실제 제품에서는 두 노드 모두에 충분한 정격의 상시 전원을 전제해야 한다.

  부가 발견: active_sta의 재접속 로직이 AP 재시작을 제때 감지하지 못한다. RX를
  리셋하면 TX도 전원 순환해야 재결합되는 경우가 있었다. 제품화 시 TX 측에 주기적
  재스캔 로직 추가가 필요하다.

  해결: USB 포트가 기판에 직접 내장된 보드(ESP32 DevKit V1)로 교체하고 A-to-C
  케이블로 전원을 공급하자 두 문제(접촉 불량, 결합 실패) 모두 해소되었다. 이는
  베어 모듈 + 외장 5핀 UART 어댑터 구성이 접촉 신뢰성과 전류 공급 두 측면 모두에서
  프로토타입 단계에 부적합했음을 보여준다.

  진단 방법론 노트: 시리얼 포트를 여는 것 자체가 ESP32의 자동 리셋 회로를 통해
  보드를 재부팅시킨다(DTR/RTS 토글). 두 보드가 서로 통신 중인 상태를 진단하려고
  한쪽 포트를 열면 그 보드가 리셋되어 기존 결합이 끊기고, 다른 쪽 보드가 재결합할
  때까지 다시 수십 초가 걸린다. 따라서 다중 보드 시스템을 시리얼로 관찰할 때는
  포트를 짧게 여러 번 여닫기보다 한 번에 충분히 길게(90초 이상) 열어두는 편이
  훨씬 안정적이었다.

4.7 미결합 상태의 CSI 취득 실패 (2-zone 확장 시도 폐기)
--------------------------------------------------------------------------------
  시도: 재실/외출 판별을 위해 RX를 2대로 늘려 침실·현관 2-zone을 구성하려 했다.
  STA 하나는 AP 하나에만 결합 가능하므로, 두 번째 RX는 결합 없이 promiscuous
  모드로 기존 TX-RX 간 트래픽을 엿듣는 방식(ESP32-CSI-Tool의 passive 예제 기반)을
  택했다.

  증상: 크래시와 설정 오류를 모두 해결한 뒤에도, 두 번째 RX를 TX·RX 바로 옆
  (30cm 이내)에 두어도 CSI 콜백이 20초간 1~2회에 그쳤다. 정상 동작 중인 RX가
  같은 시간 약 110회를 수신하는 것과 대비된다.

  진단: promiscuous raw 콜백을 별도로 등록해 확인한 결과, 일반 패킷 자체는
  대량으로 수신되고 있었다(20초에 1.3MB). 즉 전파는 도달하는데 CSI만 산출되지
  않는 상태였다.

  해석: ESP32의 CSI 추출 경로가 자신이 속한 BSS의 프레임(자신이 AP이거나 STA로
  결합한 네트워크)에 대해서만 실질적으로 동작하며, 결합 없이 엿듣는 타 BSS의
  유니캐스트 프레임에는 CSI를 산출하지 않는 것으로 판단된다. passive 예제가
  존재하는 것은 비콘 등 브로드캐스트류 프레임을 전제한 것으로 보인다.

  검증 시도: 이 해석에 따라 TX의 송신을 유니캐스트에서 브로드캐스트로 변경하면
  (192.168.4.1 -> 192.168.4.255, SO_BROADCAST) 미결합 수신기도 CSI를 얻을 수
  있을 것으로 예상했다. 코드 수정은 완료했으나, 해당 TX 보드가 부트로더 진입
  불가 상태(4.6절의 접촉 불량 재발)가 되어 실기 검증에 이르지 못했다.

  결론: 2-zone CSI 확장은 이번 개발 주기에서 폐기하고, 재실 판정은 CSI가 아닌
  스마트폰 결합 조회로 해결했다(3.4절 C안). 이 우회는 단순한 후퇴가 아니라,
  "재실 판정에 굳이 CSI를 쓸 필요가 없다"는 문제 재정의에 해당한다.

  기록 가치: promiscuous 모드에서 유니캐스트 CSI가 사실상 취득되지 않는다는 점은
  ESP32 CSI 관련 문서에 명시되어 있지 않으며, 동일한 확장을 시도하는 후속 개발에
  유용한 정보로 판단해 폐기 결정과 함께 남긴다.

5.1 핵심 검증 결과
--------------------------------------------------------------------------------
(1) 호흡 신호 검출 성공

    책상 위 정지 자세 4분 11초 캡처(2,741 샘플, 평균 11.1Hz)에 대역통과 필터 및
    Welch 스펙트럼 분석 적용.

      호흡 대역 피크 주파수   0.342Hz (분당 20.5회)
      잡음 바닥 대비 SNR      4.70배

    성인 안정 시 호흡수 범위와 부합하는 뚜렷한 주기성이 검출되어, WiFi CSI만으로
    비접촉 호흡 관측이 가능함을 실증했다.

(2) RSSI 단독 방식의 한계 실증

    실제 정지·호흡 구간에서 RSSI 표준편차는 0.43~1.13의 좁은 범위에 밀집한 반면,
    동일 구간의 CSI 진폭은 정규화 기준 +-6에 이르는 큰 변동을 보였다. RSSI는 전체
    수신 전력의 스칼라 요약값인 반면 CSI는 부반송파별 채널 응답 벡터이므로
    정보량이 수십 배 크다. 이것이 RSSI가 아닌 CSI를 써야 하는 직접적 실측 근거다.

(3) 공간별 임계값 편차와 그 해석의 정정  [본 보고서의 자기수정 항목]

    4개 조건에서 데이터를 수집하고 각 조건의 최적 임계값을 Otsu로 산출했다.

      설치 조건                최적 RSSI 임계값   정지 baseline mu   움직임 max
      책상 위                       1.48              0.802            1.83
      침대                          3.37              0.809            8.50
      바닥+침대(보드만 바닥)         1.22              0.941            2.02
      바닥                          6.32              1.182           12.79

    1차 해석(오류): 임계값이 5.18배 차이나므로 공간마다 임계값이 달라야 한다.

    재검증 결과: Otsu는 '정지 군집'과 '움직임 군집' 사이를 가르므로, 임계값은
    공간의 RF 특성뿐 아니라 그 세션에서 사람이 얼마나 크게 움직였는가에 함께
    좌우된다. 위 표에서 책상 세션은 움직임 윈도우가 1개(max 1.83)뿐이었고 바닥
    세션은 5개(max 12.79)였다. 통제된 조건(정지)만 비교하면 공간 간 편차는
    1.47배에 불과하다.

    즉 "5.18배"는 상당 부분 세션별 움직임 강도 차이의 산물이며, 순수한 공간 RF
    특성 차이는 그보다 훨씬 작다. 이 정정은 후속 설계에 직접 영향을 미쳤다.

(4) 정규화 설계 3안 비교 - 가설 하나를 기각하고 대안을 채택

    A안 (feature - mu_room)/sigma_room 정규화 후 임계값을 sigma 단위로 표현
        결과: 편차 5.18배 -> 21.84배로 악화. 기각.
        이유: 정지 상태 sigma는 움직임의 규모를 담지 못한다. 정지 sigma가 방마다
              거의 같으므로(0.18~0.29) 나누어도 압축되지 않고 오히려 증폭된다.

    B안 threshold = mu_still + k * sigma_still, k는 전 공간 공유 상수
        k    임계값 범위        편차     정지 오탐   움직임 미탐
        2.0  1.16 ~ 1.55       1.34배   1/69        0/16
        3.0  1.33 ~ 1.74       1.30배   0/69        1/16   <- 채택
        4.0  1.51 ~ 1.95       1.29배   0/69        5/16

        k=3.0 채택. 정지 상태를 움직임으로 오판하면 no-response streak가 초기화
        되어 실제 응급 상황을 은폐할 수 있으므로, 미탐보다 오탐을 더 위험하게
        가중했다.

    결론: 공간별 임계값 테이블이 아니라 정지 baseline + 공유 상수가 옳은 추상화다.
    편차 5.18배 -> 1.30배. 동시에 기기에서 Otsu가 불필요해져 임베디드 구현이
    단순해졌다.

(5) 서브캐리어 선택 - 음성 결과를 정직하게 보고

    서브캐리어 자동 선택을 임베디드 고유 기여로 설계했으나, 실제 판정 개선 여부를
    직접 측정한 결과 효과가 없었다.

      구성              호흡 검출   평균 score   피크주파수 표준편차
      전체 52개 평균     19/23       3.06         0.082 Hz
      고정 8개           20/23       3.09         0.074 Hz
      점수 상위 8개      19/23       3.04         0.067 Hz
      점수 하위 8개      20/23       2.95         0.074 Hz

    의도적으로 최악의 8개를 골라도 최상위 8개와 동등하거나 오히려 나았다. 본
    하드웨어에서 서브캐리어들이 강하게 상관되어 있어 '좋은' 것을 고르는 이득이
    없다는 뜻이다. 유일하게 측정된 이득은 피크 주파수 안정성(0.067 vs 0.082Hz).

    그럼에도 기능을 유지하는 이유는 정확도가 아니라 연산량이다. 52개 대신 8개만
    처리하면 프레임당 연산이 6.5배 줄면서 판정 품질은 동등하다. Wi-Fi 스택과
    코어를 공유하며 상시 동작하는 시스템에서 이는 실질적 이득이다.

    더 변별력 있는 지표(호흡대역 집중도, 변별폭 1.63배 vs 1.23배)도 검토했으나,
    서브캐리어당 256샘플 이력(52kB)이 필요한 반면 판정을 개선하지 못하므로
    채택하지 않았다.

(6) 호스트 레퍼런스 vs 임베디드 알고리즘 교차검증

    임베디드 C 코드를 1:1로 옮긴 Python 미러를 작성해 동일 녹화 데이터에서 비교.

      상태 판정 일치율    20/23 = 87.0%
      호흡 확정 일치율    20/23 = 87.0%
      피크 주파수 평균오차 0.032 Hz  (Goertzel 빈 간격 0.05Hz 이하)

    불일치 3건은 모두 임베디드가 SLEEP_NORMAL, 레퍼런스가 NO_RESPONSE로 판정한
    경우다. 해당 구간에 피험자는 계속 호흡 중이었으므로 임베디드 쪽이 더 정확했다.
    즉 경량화가 성능을 훼손하지 않았을 뿐 아니라, 레퍼런스의 알려진 오탐 일부를
    오히려 개선했다.

    용어 명확화: 이 87.0%는 시스템의 실사용 판정 정확도가 아니라, "PC용
    구현과 임베디드용 구현이 같은 입력에서 얼마나 같은 결론을 내리는가"를 뜻하는
    구현 동등성(implementation equivalence) 지표다. 시스템 자체의 정확도는
    이 지표가 아니라 5.1절 (7)의 분류기 성능(균형 정확도)과 5.4절의 한계 서술을
    함께 봐야 한다.

(7) 학습 기반 판정 (보조 실험)

    무인 상태(empty) 데이터를 음성 클래스로 확보해 로지스틱 회귀를 학습하고
    5-fold 교차검증으로 규칙 기반과 비교했다.

      방식                        정확도    균형 정확도
      고정 규칙 (SNR > 2.0)       66.3%     48.4%
      학습된 분류기               66.3%     68.3%

    해석상 유의점: 데이터가 불균형(호흡 69 : 무인 14)하므로 단순 정확도는 오도
    소지가 있다. 클래스 가중치를 적용하지 않은 초기 모델은 모든 샘플을 '호흡 있음'
    으로 예측하는 것만으로 83% 정확도를 기록했으나 무인 상태 재현율은 0%였다.
    이에 class_weight="balanced"를 적용하고 균형 정확도를 주 지표로 채택했다.

    균형 정확도 기준 고정 규칙은 48.4%로 무작위 추측 수준인 반면 학습 분류기는
    68.3%를 달성했다. 무인 상태 검출 재현율은 21%(3/14) -> 71%(10/14)로 향상됐다.

    다만 학습 데이터가 137개 윈도우에 불과하므로 본 시스템의 주 판정 경로는 여전히
    적응형 DSP + 상태기계이며, 분류기는 개념 증명 단계의 보조 실험으로 위치시킨다.
    추론 자체는 특징 5개의 내적 한 번이므로 ESP32 이식에 아무 부담이 없다.

5.3 검증 현황 (정직한 구분)
--------------------------------------------------------------------------------
  [실기 하드웨어에서 검증 완료 - 전 계층]
    - 엣지 파이프라인 기동 (FreeRTOS 큐 + CSI 태스크 + 판정 태스크)
    - CSI 콜백 실수신 (cb=898, ringfill=256으로 25.6초 창 완전 충전)
    - 10초 판정 사이클 정확한 주기 동작
    - Goertzel 호흡 검출 실동작: 실제 사람 근처에서 ACTIVE -> NO_RESPONSE ->
      SLEEP_NORMAL -> ACTIVE 상태가 실시간으로 전이됨. 여러 창에서 peak_hz=0.300
      으로 일관되게 검출되었고, 독립 경로인 자기상관 결과(0.27~0.33Hz)도 근접해
      상호 검증됨
    - 정지 baseline 자동학습(EWMA) 실동작: 관찰 중 motion_thr가 1.560->1.494로,
      breath_thr가 1.540->3.959로 실시간 갱신됨 (5.1절 (4)에서 설계한 정지
      baseline + 공유 상수 k 구조가 실제로 학습 상태를 갱신하는 것을 확인)
    - 60초 히스테리시스 카운터, NVS 로드
    - GPIO4 LED / GPIO5 PWM 부저 구동
    - FAULT / EMERGENCY 분리: 로그상 streak=0, data_streak=6 -> FAULT 판정,
      물리적으로 적색 LED만 점등 + 부저 무음 확인. TEST_LED 벤치 명령으로
      LED 단독 구동도 별도 확인
    - 빌드 자원: DRAM 24.6% 사용(136kB 여유), 파이프라인 정적 구조체 약 7.3kB
    - 스마트폰 기반 재실 판정 4단 구조: PINNED 매칭, ANY 축퇴, NVS 학습 복원
      (단말 3대, 재부팅 후 복원), 자격 규칙(상시 결합 기기 배제) 모두 확인
      (3.4절)

  [녹화 데이터 기반 검증 완료]
    - CSI 수집 및 호흡 검출 (캡처 모드, 2,741 프레임)
    - 임계값 정규화 설계 비교 (137 윈도우, 4개 공간)
    - 호스트-임베디드 교차검증 (87.0% 일치)
    - 분류기 학습 및 교차검증

  [미검증 - 구현만 완료]
    - 등록 트리거용 BOOT 버튼(GPIO0) 입력 및 LED 점멸 피드백: 3개 프로젝트
      빌드는 통과했으나 실기 버튼 입력 테스트는 수행하지 못했다. 동일 기능을
      시리얼 명령(REGISTER)으로는 실기 검증했으므로 등록 로직 자체는 확인된
      상태이며, 미검증 범위는 버튼 입력 경로에 한정된다.
    - 3단 ADOPTED 자동 채택: 활성화에 실제 외출 3회 관측이 필요해 프로토타입
      기간 내 도달하지 못했다.
    - TX 브로드캐스트 송신 전환: 미결합 수신기의 CSI 취득 가능성을 확인하기
      위해 코드는 수정했으나, 해당 TX 보드가 부트로더 진입 불가 상태가 되어
      실기 검증에 이르지 못했다 (4.6절, 4.7절).

  [부분 확인 - 후속 과제]
    - 서브캐리어 자동 선택의 온디바이스 동작: 파이프라인이 정상적으로 판정을
      산출했으므로 서브캐리어 데이터 처리 경로 자체는 살아있음을 간접 확인했으나,
      "N개 서브캐리어 선택 완료" 로그 문구 자체는 반복적인 보드 재부팅(진단 중
      포트를 여러 번 여닫으며 자동 리셋 유발) 때문에 포착하지 못했다. 선택에는
      600프레임(약 1분) 연속 수신이 필요하다.

5.4 한계
--------------------------------------------------------------------------------
  1) 감지 범위: TX-RX 유효 거리 약 1~2m. 침대 길이 수준에서 연결 자체가 불안정한
     현상을 실측했다. 실사용에는 외장 안테나 또는 다중 노드 구성이 필요하다.
  2) 데이터 규모: 137 윈도우(단일 피험자, 4개 공간)는 통계적 일반화에 부족하다.
     분류기 성능은 개념 증명 수준이다.
  3) RF 간섭: 2.4GHz 대역은 이웃 공유기·블루투스·전자레인지와 공유된다. 간섭 시
     패킷 손실로 샘플링 레이트가 저하되며, 손실이 집중되면 주기성 판정이 왜곡될
     수 있다. 다만 이 취약성 자체가 '환경이 성능을 지배한다'는 논지를 보강한다.
  4) 원격 알림 미구현: 현재 알림은 로컬 한정. 가족·복지사 통보는 후속 과제다.
  5) TX 재결합 지연: active_sta가 AP 재시작을 즉시 감지하지 못해 재결합에
     지연이 발생할 수 있다 (4.6절). USB 내장형 보드 교체로 접촉·전원 문제는
     해소되었으나 이 재결합 로직 자체는 아직 개선하지 않았다.
  6) 재실 판정의 전제: 스마트폰 기반 판정은 거주자가 외출 시 폰을 소지함을
     전제한다. 폰을 두고 나가면 외출을 재실로 오판하나, 이는 과잉 경보 방향이라
     안전하다. MAC 무작위화는 4단 축퇴 구조로 완화했으나(3.4절) 잔여
     위험이 있다.
       - 3단 ADOPTED는 실제 외출 3회를 관측해야 활성화되므로 미검증이다.
         등록(REGISTER)을 거치면 이 공백은 메워지나, 등록을 생략하고 설치하면
         학습이 쌓이기 전 수일간 외출 억제가 동작하지 않는다.
       - 등록 트리거로 BOOT 버튼을 재활용해 PC 없이 설치할 수 있게 했으나,
         버튼 입력과 LED 점멸만으로는 "누가 등록되었는지"를 현장에서 확인할 수
         없다. 등록된 MAC 확인에는 여전히 시리얼 로그가 필요하다.
       - 자동 채택은 이탈 횟수 최다 단말을 고르므로 방문자 폰이 채택될 가능성은
         낮으나, 거주자가 외출이 극히 드물면 역전될 여지가 남는다.
     보조 신호인 CSI 이탈 추정은 임계값(6.0 sigma)이 실측 이탈 데이터가 아닌
     보수적 추정치이며, 아직 검증되지 않았다.

6. 개발 결과물의 파급력 및 기대효과

6.1 사회적 파급력
--------------------------------------------------------------------------------
  고독사 위험 완화에 기여 가능한 보완 수단
    현행 응급안전안심서비스는 의식이 있는 상태의 능동적 호출에 의존한다. 본
    시스템은 능동적 호출 없이도 장시간 호흡 신호 소실을 감지해 알릴 수 있어,
    기존 서비스가 원리적으로 대응하기 어려운 영역을 보완할 잠재력이 있다.
    다만 5.4절의 한계(감지 범위, 간섭, 소규모 검증)로 인해 이 자체로 고독사를
    예방한다고 주장하지는 않으며, 기존 안전망에 더하는 하나의 보조 신호로
    자리매김하는 것이 현재 검증 수준에 맞는 위치다.

  프라이버시 장벽 해소
    사고가 가장 빈번한 침실·욕실은 사생활 민감도가 극히 높아 카메라 설치가 사실상
    불가능하다. 영상을 수집하지 않는 본 방식은 이 영역에 적용 가능한 대안이다.

  디지털 격차 완화
    스마트폰 조작, 앱 설치, 기기 착용·충전이 일절 필요 없다. 전원만 연결하면
    동작하므로 고령층의 기술 수용 장벽이 극히 낮다.

6.2 시장성
--------------------------------------------------------------------------------
  제조 원가   부품비 약 2만원 (양산 시 추가 절감 여지)
  1차 시장    지자체 독거노인 돌봄사업 - 저단가 대량 보급
  2차 시장    요양원·실버타운 야간 순회 보조
  3차 시장    1인 가구 일반, 영유아 수면 모니터링, 반려동물 모니터링
  경쟁 우위   보건복지부 응급안전안심서비스가 쓰는 전용 FMCW/mmWave 레이더 칩은
              개당 3만~15만원대인 반면, 본 방식은 동일 원리(반사파 위상 변화로
              호흡 검출)를 개당 3천~7천원대 범용 WiFi 칩으로 구현해 원가 구조가
              근본적으로 유리하다 (1.5절 유사 사례 비교 참조)

  운영 비용   클라우드 추론 비용 0원 / 서버 불필요 / 인터넷 불필요 / PC 불필요
              연산 부하보다 RF를 상시 켜두는 전력이 지배적이므로, DSP 연산을 몇
              천 번 더 수행한다고 전력 비용이 의미 있게 증가하지 않는 구조다.

6.3 기술적 활용성 및 발전 가능성
--------------------------------------------------------------------------------
  모듈 재사용성
    적응형 baseline 계층은 CSI 센싱에 국한되지 않는다. 정지/활동 두 모드를 갖는
    임의의 센서 신호에 대해 임계값을 자동 산출하는 범용 모듈로, 진동·음향·전류 등
    다른 임베디드 센싱 응용에 그대로 이식 가능하다.

  발전 로드맵

  [완료] = 실기 검증까지 끝난 항목. [설계] = 구조·코드는 있으나 실사용 검증 전.
  [계획] = 아직 코드가 없는 향후 과제. 아래 표는 이 구분을 명시해 "이미 되는 것"과
  "하기로 한 것"을 섞어 읽지 않도록 한다.

    [완료] ESP32 단독 엣지 파이프라인 (CSI 취득~알림, 5.3절 실기 검증)
    [완료] 정지 baseline 적응형 보정 (EWMA + 공유 상수, 5.1절 (4))
    [완료] 스마트폰 MAC 기반 재실/외출 판정 (3.4절, 실기 검증)
    [폐기] CSI 기반 2-zone 재실 상태기계 -- 4.7절. 위 항목으로 대체
    [폐기] 스마트폰을 CSI 송신원으로 사용 -- 3.4절 B안. 배터리 소모 근거
    [계획] 공유기 비콘 재활용 TX (댁내 WiFi 공유기가 있으면 전용 TX 보드 불필요,
           RX만 설치) + 자체 폐쇄망 TX/RX (공유기 없는 가구용) 이원 지원
    [완료] 랜덤 MAC 대응 -- PINNED/REGISTERED/ADOPTED/ANY 4단 축퇴 (3.4절)
    [완료] 학습 상태 NVS 영속화 -- 재부팅 후 복원 실기 확인
    [완료] 상시 결합 기기의 재실 판정 점유 차단 -- 이탈 이력 기반 자격 규칙
    [완료] 설치 직후 학습 공백기 대응 -- REGISTER 등록 절차 (실기 검증)
    [완료] 오등록 방지 -- 창 종료 시 단일 후보만 등록, 애매하면 거부 (실기 검증)
    [설계] 등록 절차의 현장 사용성 -- BOOT 버튼(GPIO0) 재활용으로 PC 없이
           등록 가능. 부품 추가 0개. 빌드 완료, 실기 버튼 테스트는 미수행
    [계획] 등록 결과의 현장 확인 수단 -- 등록된 MAC 확인에 아직 시리얼이 필요.
           설정용 웹 UI 또는 LED 패턴 피드백
    [계획] MQTT+FCM+Android 원격 알림 (edge_mqtt.h 스캐폴드 존재, 실기 미검증)
    [계획] 다수 피험자 데이터 확보 -> 분류기를 주 판정 경로로 승격
    [계획] 저전력 프로토콜(LoRa 등) 기반 원격 알림 (근거리 무선망 환경 대응)
    [계획] TX 측 주기적 재스캔 로직 추가 (4.6절 부가 발견)
    [계획] 개인별 생활 패턴 학습 -> 수면 시간대 자동 산출 (현재는 고정 시간대)

  연구적 확장
    공간별 채널 특성 데이터는 건축 재료·공간 구성과 무선 센싱 성능의 상관관계
    연구로 확장 가능하다. 다만 5.1절 (3)에서 확인했듯 이 상관관계를 주장하려면
    움직임 강도를 통제한 실험 설계가 필수적이며, 이는 후속 연구의 출발점이다.

  추가1  임베디드 이식 전 파이프라인 C 이식, 정규화 설계 재검증,
                       호스트-임베디드 교차검증, 실기 테스트              [완료]
  추가2  재실 판정     CSI 2-zone 시도 및 폐기(4.7절), 스마트폰 결합 조회
                       기반 재설계, 4단 축퇴 구조, 등록 절차, NVS 영속화  [완료]

  두 차례의 추가 단계는 모두 당초 계획에 없었고, 각각 다른 종류의 한계를 마주해
  착수했다.

  추가1은 구조적 한계였다. "ESP32로 수집하고 호스트 PC에서 처리한다"는 구성은
  임베디드 SW 작품으로서 가장 큰 약점이라고 판단해 전 파이프라인을 온보드로
  옮겼다.

  추가2는 알고리즘의 한계였다. 무동작을 수면과 이상으로 가르는 데까지는
  성공했으나, "외출"과 "이상"은 CSI 상에서 동일하게 보인다는 문제가 남아 있었다.
  수면 시간대 게이팅은 완화책일 뿐이었다. 두 번째 CSI 존을 두는 방향을 먼저
  시도했다가 하드웨어 한계로 폐기하고(4.7절), 재실 판정에 굳이 CSI를 쓸 필요가
  없다는 문제 재정의를 거쳐 스마트폰 결합 조회 방식으로 전환했다(3.4절).

부록. 실행 방법

  # 개발 환경 활성화
  get_idf

  # TX 보드 (송신 전용)
  cd ~/Desktop/ESP_project_2026/ESP32-CSI-Tool/active_sta
  idf.py -p <TX포트> flash

  # RX 보드 (CSI 취득·판정·알림. EDGE_MODE=1 이면 standalone)
  cd ~/Desktop/ESP_project_2026/ESP32-CSI-Tool/active_ap
  idf.py -p <RX포트> flash

  # 주의: sdkconfig는 형상관리 대상이 아니므로 최초 빌드 시
  # sdkconfig.defaults가 적용된다. 특히 CONFIG_ESP32_WIFI_CSI_ENABLED=y가
  # 없으면 빌드는 성공하지만 런타임에 esp_wifi_set_csi(1)이 실패해 부팅이
  # 반복된다. sdkconfig를 임의로 지우고 재생성했다면 이 값을 확인할 것.

  # 이후 RX 보드는 PC 없이 단독 동작. 시리얼은 개발용 상태 출력만 제공.
  # EDGE 행 형식:
  #   EDGE,state,motion,breath_score,peak_hz,ac_hz,ac_strength,streak,
  #        data_streak,frames,dropped,motion_thr,breath_thr,calibrated,alert,
  #        away_inferred
  # EDGE_DIAG 행 형식:
  #   EDGE_DIAG,cb,nullbuf,lastlen,rejected,ringfill,presence=<티어>/<HOME|AWAY>

  # ---- 설치 시 1회: 거주자 단말 등록 --------------------------------------
  # 방법 A (PC 불필요) : RX 보드의 BOOT 버튼을 2초간 길게 누른다.
  #                      LED가 깜빡이면 60초 등록 창이 열린 것이다.
  #                      그 사이 거주자 폰의 WiFi를 껐다 켠다.
  #                      다른 기기는 네트워크에서 분리해 둘 것.
  # 방법 B (시리얼)    : REGISTER 를 전송하고 위와 동일하게 진행.
  # 창 종료 시 새로 결합한 단말이 2대 이상이면 등록이 거부되고 후보 MAC이
  # 출력된다. 이때는 목록을 보고 아래처럼 직접 지정한다.
  #   REGISTER AA:BB:CC:DD:EE:FF
  # 등록 결과는 NVS에 남으며, 이후 매 부팅 로그에서 확인할 수 있다.
  #   edge_presence: restored from NVS: N device(s), registered device is ...
  # 등록을 생략해도 동작하지만, 자동 학습이 근거를 쌓기 전 수일간은 외출
  # 억제가 동작하지 않는다(항상 재실로 판정).

  # [개발용] 알림 회로 단독 점검
  #   TEST_LED   LED만 점등 (부저 무음)
  #   ALERT_ON   LED + 부저
  #   ALERT_OFF  해제
  # 판정 태스크가 10초마다 재평가하므로, 수동 명령의 효과는 다음 주기에
  # 덮어쓰일 수 있다. 10초 이내에 확인할 것.

  # [개발용] 호스트 레퍼런스 구현 실행 (EDGE_MODE=0 펌웨어 필요)
  python3 data/live_monitor.py /dev/cu.usbserial-0001 --label bedroom

  # [개발용] 임계값 설계 검증
  python3 data/validate_normalization.py

  # [개발용] 호스트-임베디드 교차검증
  python3 data/validate_embedded.py

  # [개발용] 분류기 재학습
  python3 data/train_classifier.py
